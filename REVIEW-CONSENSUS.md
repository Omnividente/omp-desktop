### F-3. `keyring = "4.1.5"` без явных features · Приоритет: **P1 (проверить)** · Статус: **OPEN**

**Позиция Fabo (2026-07-26):** В `Cargo.toml` для `keyring` не заданы features — не зафиксировано, какие платформенные бэкенды (в частности secret-service/DBus на Linux) реально компилируются. Таймаут + файловый fallback страхуют от зависания и потери данных, но на Linux это может означать постоянную работу через `provider-secrets.json` вместо системного хранилища. Предложение: явно перечислить features под целевые платформы (Windows/macOS/Linux), проверить сборку на Linux и зафиксировать результат здесь.

### F-4. «Брошенный» keyring-поток после таймаута · Приоритет: **P2** · Статус: **OPEN**

**Позиция Fabo (2026-07-26):** `run_keyring_operation_with_timeout` при таймауте оставляет рабочий поток жить: он может позже завершить запись в хранилище уже после того, как приложение переключилось на fallback — состояние keyring и fallback-файла может разойтись. Предложение: либо осознанно принять и задокументировать комментарием в `secrets.rs`, либо добавить поколение/флаг отмены, который поток проверяет перед записью.
